## 2. Скелет проекта Godot: сцены и синглтоны

### 2.1. Дерево autoload-синглтонов (обязательный стандарт)

| Autoload | Обязанность | Ключевые API |
|---|---|---|
| `EventBus` | центральная шина событий (сигналы вместо прямых связей нод) | `EventBus.coin_changed.emit(...)` и т.п. |
| `App` | конфигурация, платформа, жизненный цикл, «где мы сейчас» | `App.platform`, `App.is_ru_build()` (определяется по feature/домену билда), `App.quit_requested` |
| `SaveManager` | чтение/запись/миграция сейвов | `load_game()`, `save_game()`, `wipe()` |
| `Timekeeper` | единое игровое время (см. §6) | `now()`, `server_delta`, `is_clock_sane()` |
| `AudioManager` | музыка, SFX, громкости, слои | `play_music(loop_id)`, `sfx(id, pitch_var)` |
| `Haptics` | вибрация (тонкие: 10–30 мс, не дёргать) | `tap()`, `success()`, `error()` |
| `I18n` | локализация (ru/en минимум) | `tr_key(id)` |
| `Monetization` | фасад платежей/рекламы (§ монетизация в каждом ТЗ и в доке 04) | `show_rewarded(cb)`, `purchase(sku)`, состояние `is_ads_consent` |
| `Analytics` | шлёт события в GameAnalytics (+AppMetrica на RU-билде опц.) | `track(event, props)` |
| `Notifications` | локальные уведомления через плагин Notification Scheduler | `schedule(...)`, `cancel(...)` |

Правила:
- **UI-сцены не общаются напрямую** — только через `EventBus` и сигналы. Это позволяет менять экраны, не ломая логику.
- Вся игровая логика — в **не-UI синглтонах/нодах-менеджерах** (сцена «Core»): UI подписывается на события и читает состояние.
- Ноды, живущие вечно: `Core` (логика), `UICanvas` (смена экранов через `change_scene_to_*` или собственную ScreenStack).
- **Один тик-таймер.** Доход и все игровые таймеры считает один нод (`Economy`) 10 раз/секунду; UI обновляется по сигналу `EventBus`, а не в `_process` каждой панели. Меньше расход батареи, проще тесты и симулятор.
- **Большие числа.** После ~1e15 `float` теряет точность, `int` переполняется ~9.2e18. Свой класс `BigNum` (мантисса + экспонента) с форматированием `1.23 Qa` / `1.23e15` (переключатель в настройках). Все формулы баланса, сейвы и UI работают только через него — кликеры гарантированно упираются в лимиты float.
- **Игровое поле принимает `InputEventScreenTouch`**, а не UI-кнопки в «горячей» зоне: даёт мультитач (кликер «двумя пальцами» — стандарт ожиданий жанра) и убирает накладные расходы темы оформления на самых частых тапах.

### 2.2. ScreenStack — «юзер-френдли» навигация

Вместо жёсткого `change_scene` — лёгкий стек экранов: `push(screen) / pop() / replace()`. Даёт бесплатно: кнопку «назад» на Android (через перехват `NOTIFICATION_WM_GO_BACK_REQUEST`), анимации переходов, защиту от двойного нажатия. Скелет:

```gdscript
# screens.gd (autoload)
var stack: Array[String] = []
func push(screen_path: String) -> void:
    if stack.size() and stack.back() == screen_path: return   # анти-двойной тап
    stack.append(screen_path); _apply()
func pop() -> void:
    if stack.size() > 1: stack.pop_back(); _apply()
```

## 3. Сохранения: надёжно и без боли

1. **Формат:** один JSON-файл на игру: `user://save_v3.json` (версия в имени помогает при миграциях). Никакого бинарного сериализатора — читаемость и дебаг важнее.
2. **Атомарность:** запись → сначала `save.tmp`, затем `DirAccess.rename_override` (или `FileAccess` + перезапись). При краше не остаётся битого файла.
3. **Частота:** автосейв каждые 15 сек + при `NOTIFICATION_APPLICATION_PAUSED`/`WM_GO_BACK_REQUEST`/`NOTIFICATION_WM_CLOSE_REQUEST`. Перед оффлайн-расчётами — тоже сейв.
4. **Миграции:** в SaveManager `SAVE_VERSION` + массив функций-миграций. Старая версия → последовательный прогон миграций до актуальной.
5. **Валидация при загрузке:** sanity-проверки (не-отрицательные балансы, существующие id элементов). Битые файлы — не краш, а «начать заново, сохранив битый как `corrupt_backup.json`».
6. **Античит-минимум:** играм не нужен серьёзный античит (это не PvP-экномика), но «честность» важна для мета-слоёв (таблица алхимика, гонка): **все спорные решения принимает сервер**, клиент не является источником истины (см. §7). Подделка локального сейва вредит только самому игроку.

## 4. Игровое время и оффлайн-прогресс

Для всех трёх игр нужна аккуратная работа со временем (оффлайн-заработок, окна запусков, таймеры варки).

**Timekeeper (autoload):**
- `server_now`: при каждом успешном HTTP-ответе сервер возвращает заголовок/поле времени; Timekeeper вычисляет `delta = server_now - local_now` и хранит «исправленное» время `trusted_now = local + delta`.
- Если сети нет — используем локальное время и помечаем состояние `CLOCK_UNVERIFIED`.
- **Защита от перевода часов вперёд:** оффлайн-начисления считаются по `trusted_now`, но не дальше лимитов (см. лимиты в каждом ТЗ, обычно 8–24 ч), плюс сервер валидирует критические действия (запуск ракеты, первооткрытие) по своему времени.
- Перевод часов **назад** не должен «отматывать» прогресс: храним время последнего расчёта в сейве; если новое время < сохранённого — игнорируем расхождение.

Формула оффлайн-начисления (общая для idle-частей): `earn = rate_per_sec * min(offline_sec, cap)`, кап и rate — из баланса игры.

## 5. Android: жизненный цикл, разрешения, UX-системные требования

### 5.1. Жизненный цикл

- `NOTIFICATION_APPLICATION_PAUSED` → пауза игровых таймеров (кроме real-time окон Launch Day, их ведёт Timekeeper по wall-clock), автосейв, мьютинг звука.
- `NOTIFICATION_APPLICATION_RESUMED` → пересчёт оффлайн-начислений, обновление «живых» UI (таймеры), при необходимости ре-валидация сети.
- **Back-кнопка:** `NOTIFICATION_WM_GO_BACK_REQUEST` → закрыть верхний экран стека / открыть диалог «Свернуть?» в главном меню. В мини-играх (обратный отсчёт Launch Day) back блокируется и пишет «Игра идёт — заверши отсчёт!».
- Ориентация: портрет для ALCHEMIST'S LOOP и Quantum Biology; Launch Day — портрет тоже (вертикальный скролл штабов), без автоповорота на старте (зафиксировать портрет — меньше крашей и тестов).

### 5.2. Safe area и вырезы

Все UI-макеты верстаются внутри **safe area**: `DisplayServer.get_display_safe_area()` + `canvas.transform` отступы; обязательный MarginContainer «обвязка» с величиной из настроек. Тест на эмуляторах/девайсах с каплей (Pixel 6-класс) и с «монобровью».

### 5.3. Разрешения (AndroidManifest)

| Разрешение | Нужно | Когда |
|---|---|---|
| `INTERNET` | всем (бэкенд/аналитика/реклама) | всегда |
| `POST_NOTIFICATIONS` | Launch Day (и уведомления готовности в Alchemist) | рантайм-запрос (Android 13+), в момент первого планирования уведомления |
| `VIBRATE` | всем (хаптика) | всегда |
| `RECEIVE_BOOT_COMPLETED` | Launch Day | переживание запланированных уведомлений после перезагрузки устройства |
| `SCHEDULE_EXACT_ALARM` | **не использовать** | Google Play разрешает его приложениям-будильникам/календарям; играм грозит отклонение. Точность окна обеспечивается дизайном: окна запуска длиной ≥10 мин + inexact-напоминания + проверка в игре. |
| Storage/фото | нет | сохранение картинок через MediaStore/Share intent, без разрешений |

### 5.4. Android-специфика производительности

- fps: цель 60, `Engine.max_fps = 60` в релизе.
- Батарея: минимум «вечных» анимаций на главном экране; партиклы паузить при бездействии (нет тапов 20 с → «тлеющий режим», снижение particle amounts).
- Профилировать на слабом эталоне: устройства с Adreno 610/650 (Redmi Note 10-класс) и Mali-G52.
- Текстуры: все атласы — POT или оптимизированные под мобильные сжатия; `import settings`: lossless для UI-элементов, `VRAM Compressed` для арта.

## 6. UX-стандарты (общие для всех игр)

1. **Тач-цели ≥ 48×48 dp** (~88–126 px при проекции 1080p, считать через `DisplayServer.screen_get_scale()`), межкнопочные зазоры ≥ 8 dp. Всё, что меньше — в «спокойных» зонах.
2. **Отклик мгновенный:** каждое нажатие → визуальная реакция (scale 0.94 + тень) и SFX ≤ 100 мс после тапа. Нет «мёртвых» нажатий: у кнопок с асинхронным действием — состояние `disabled` + спиннер.
3. **Анти-двойной тап:** глобальный guard 200 мс на критичные кнопки (покупки, запуск).
4. **Fitts и большой палец:** часто используемые кнопки — в нижней трети экрана; свайпы — только дополнительные.
5. **Одна главная цель на экран.** Вторичные действия — иконки с подписями, не наоборот.
6. **Прогресс виден всегда:** числовые счётчики с анимацией «тика», полосы прогресса с «вспышкой» при апгрейде.
7. **Оффлайн-приветствие:** при возврате — экран «Пока вас не было…» с начисленным и кнопкой «Забрать» (тап = позитив).
8. **Ошибки сети не блокируют:** действия в офлайне ставятся в очередь (см. серверные секции в ТЗ), UI показывает «⏳ синхронизация…», а не ошибку.
9. **Доступность-минимум:** крупный режим шрифта системы не ломает макет (тест), контраст текста ≥ 4.5:1, уведомления дублируются визуально+звуком+вибрацией.
10. **Хаптика:** лёгкая (10 мс) на тапы-добычу, средняя (30 мс) на успех, двойной короткий сигнал на ошибку. Не вибрировать при rewarded-рекламе и в окнах, где игрок тапает быстро (иначе «дрожит»).

## 7. Серверный слой (общий подход)

У всех трёх игр есть социальная/мета-составляющая, требующая лёгкого бэкенда. Рекомендация: **один общий бэкенд-сервис** (Go/Node/Python, Postgres, обычный JSON REST + long-poll или WebSocket для онлайн-присутствия), развёрнутый на одном хостинге (VPS/облако в РФ + реплика в EU для GP-аудитории — решается по географии запуска).

Модули бэкенда (общие): `auth` (device-id + опционально Google Sign-In/VK ID), `profiles` (никнейм), `content_registry` (см. ниже), `notifications` (толкать push через FCM? — для MVP достаточно локальных уведомлений; push-сервер — этап 2), `telemetry` (приём событий), `moderation` (жалобы на имена/картинки), `rate_limit` (анти-спам).

Клиентский слой: `BackendClient` autoload с очередью событий (offline-first): каждое действие кладётся в очередь на диске, уходит при сети, ответы применяются идемпотентно (`client_event_id`). Таймауты 5–10 с, повтор с экспоненциальной задержкой, лимит очереди.

**Правило честности мета-слоёв:** если действие влияет на «общий мир» (открытие элемента, вклад в гонку) — решение принимает сервер. Клиентские данные — только запрос.

## 8. Аналитика

**Провайдер:** GameAnalytics — официальный Godot-плагин 3.x (AssetLib, MIT) поддерживает Godot 4.5+; бесплатен; не привязан к Google (важно для RU-билда). На RU-билде опционально параллельно AppMetrica (для когортного анализа РФ-трафика). Запрещено слать персональные данные; device id генерируется на клиенте.

**Стандарт имён событий:** `{noun}_{action}` в snake_case, проперти в camelCase:

```gdscript
Analytics.track("combine_try", { "left": "fire", "right": "water", "result": "none", "source": "recipe" })
Analytics.track("purchase_start", { "sku": "gem_pack_1", "store": "google" })
```

События, обязательные во всех играх (полный набор под игру — в её ТЗ):
- `session_start/end` (длина, источник входа: push/иконка), `tutorial_start/step_done`, `level_*` (стадии), `ads_impression/click`, `rewarded_available/start/finish`, `iap_start/success/fail`, `rate_offer_shown/clicked`, `crash` (плюс крашлити из Godot/Android).
- `time_shift_detected` (сработала защита от перевода часов).

**Метрики дашборда:** D1/D7/D30 retention, сессий/день, длина сессии, ARPDAU, конверсия в IAP, % дней с rewarded, crash-free, медиана времени до «Aha-момента» (событие киллер-фичи).

**Согласие (consent):** если билд виден в EEA — собственный диалог согласия (GDPR) до инициализации рекламных SDK; сохранять выбор; передавать в SDK (`setUserConsent` у плагинов Яндекса; у AdMob — своя логика/вопрос в настройках политики). Для РФ — базовая политика конфиденциальности + пункт о рекламе (152-ФЗ о рекламе; детали в доке 04).

## 9. Графика: общий конвейер «просто и дёшево»

Общий принцип для всех трёх игр — **никакого тяжёлого 3D/рендера**: 2D-сцены + шейдеры + процедурная генерация + ограниченный набор «дорогого» арта, сделанного с помощью ИИ-API и дорисованного.

### 9.1. Пайплайн арта (рекомендация)

1. **База:** генерация через image-API по стиль-промпту (например, pollinations.ai, бесплатные лимиты; либо локально Stable Diffusion при наличии GPU). Получаем 20–40 вариантов фонов/персонажей-«заготовок».
2. **Селекция:** отбор 3–5 «сильных» работ, которые становятся **опорными точками стиля**.
3. **Перевод в игру:** лёгкая пост-обработка (тонирование под палитру игры, кроп под экраны), сборка спрайтов-объектов.
4. **Всё остальное — процедурно** (см. ниже) — анимации, иконки, частицы, фоны-лупы.
5. UI-набор: готовый CC0-пак (например, наборы в стиле «кнопки/рамки» с itch.io по лицензии CC0) или простые 9-patch, нарисованные за вечер.
6. Палитра: зафиксировать 16–32 цвета из готовой палитры (например, Lospec) — целостность стиля «бесплатно»; сгенерированный арт приводить к палитре (Indexed mode в Aseprite/Krita/Photopea).
7. Каркас UI (панели, кнопки, обводки, тени, скругления) — `Theme` + `StyleBoxFlat`, вообще без текстур: дёшево, чётко на любых DPI, перекрашивается под игру за минуты.
8. Аватары персонажей (гости лавки, «менеджеры», биологи музея) — бесплатные аватар-API с CC0-стилями (DiceBear и аналоги) по seed: можно даже в рантайме.

### 9.2. Что делается процедурно (без генераций)

- **Фоны-лупы** (шум, звёзды, туман, свечения) — `FastNoiseLite` + `GradientTexture2D` + медленная анимация через шейдер.
- **Иконки элементов/генов/деталей** — скрипт `tools/gen_icons.py` рисует (Pillow) по правилам категорий → атлас. Пример: в АЛХИМИКЕ иконка вещества выводится из категории (цветовая пара + базовый глиф-силуэт) — **новые элементы, открытые сообществом, получают иконку автоматически** без участия художника.
- **Партиклы** — стандартные CPUParticles2D/GPUParticles2D с кастомными шейдерами.
- **Анимации UI** — Tween-библиотека (стандарт: scale+alpha 120–180 мс, easing out_cubic).

### 9.3. Лицензии

Весь арт фиксировать в `assets/art/LICENSES.md`: ИИ-сгенерированное — помечать «AI-generated, style anchor» (для карточки стора это не требуется, но для внутренней дисциплины — да); CC0 — имя автора и ссылка; шрифты — OFL (кириллица обязательна!). Никакого арта с неизвестной лицензией.

## 10. Производительность-инварианты

- Императив: **0 allocation-мусора в `_process`** (пулы, без создания строк в циклах).
- Ноды не плодить: пулы партикл-вспышек, повторное использование попапов.
- Canvas: минимум `clip_content` на больших областях; отключить 2D-сглаживание там, где не нужно.
- Иконки/кнопки — атлас одним спрайтом-регионом (`AtlasTexture`), а не десятки файлов.
- Проверка на эталоне: 60 fps, загрузка сейва 1000+ сущностей < 300 мс, тёплый старт < 3 с на Redmi-классе.

## 11. Аудио: инфраструктура и генерация «вайбовых» саундтреков

### 11.1. Микшер

- Bus-дерево: `Master → Music | SFX | UI | Ambient`. Громкости: Music 0.5, SFX 1.0, UI 0.9. Музыка авто-дак (sidechain через `AudioEffect`? — в Godot проще: при SFX-событиях «громких» типов на 150 мс опускать Music до 0.7).
- Слои музыки: `AudioStreamPlayer` на каждый слой (bass / pads / lead / perc). Смена «интенсивности» = смена громкости слоёв, а не смена файла. Это даёт дешёвые динамические переходы (бой/строительство/покой).
- В Godot 4.3+ для слоёв с переключением **строго по долям** правильнее `AudioStreamInteractive` (сегменты/переходы, квантование по битам) и `AudioStreamSynchronized` (вертикальные слои). Используем их, когда лупы уже сгенерированы и известен BPM: переключение слоя (например, «вошёл в окно запуска») встаёт ровно в долю без ручного кода. Для черновых прототипов достаточно громкостного микса на `AudioStreamPlayer`, затем переносим в synchronized-слои.
- Все лупы — строго одинаковой длины в тактах и в одном BPM, тогда слои можно миксовать на лету.

### 11.2. Генерация музыки без музыканта (рецепт для всех трёх игр)

Инструмент: Python + `numpy` → WAV (или `ffmpeg` для конвертации в OGG/Vorbis). Пайплайн лежит в `common/audiogen/`:

0. Быстрый запасной вариант (если писать синтезатор некогда): SFX — jsfxr/ChipTone (WAV, секунды), лупы — BeepBox / Bosca Ceoil / LMMS (OGG). Правила те же: контент свой или лицензионно чистый, лупы одной длины в тактах и одного BPM, чтобы работали слои (§11.1).

1. Выбрать BPM, тональность и «инструментальный набор» под вайб игры (таблица — в ТЗ каждой игры).
2. Прогнать генератор: базовые паттерны (аккорды из прогрессии по кругу, арпеджио, бас по корням, перкуссия: шумовые хэты/кик синтезом).
3. Прослушать N=5–10 вариантов (разные сиды), отобрать, свести в `assets/audio/music/`.
4. Тот же генератор делает **варианции**: intro (без ударных), main, riser (для финалов/обратного отсчёта).

Минимальный работающий генератор (стиль «чистый эмбиент-пад», используется как база):

```python
import numpy as np, wave
SR = 22050
def tone(freq, dur, vol=0.25, decay=4.0):
    t = np.linspace(0, dur, int(SR*dur), False)
    env = np.exp(-decay*t)
    # мягкий тон = синус + 2 гармоники, лёгкое детюнинг-хоровое звучание
    det = np.sin(2*np.pi*freq*1.003*t) + np.sin(2*np.pi*freq*0.997*t)
    return vol*env*(np.sin(2*np.pi*freq*t)*0.6 + det*0.2)

chords = {  # ам-эмбиент: Am – F – C – G (частоты корней)
 'A2':110.0,'F2':87.31,'C3':130.81,'G2':98.0}
s = np.zeros(SR*8); bpm=72; beat=60/bpm
# 2 такта по 4 доли: аккорд каждую долю = плавная «дышащая» подложка
for i,f in enumerate([chords['A2'],chords['F2'],chords['C3'],chords['G3']] if 'G3' in chords else [110.0,87.31,130.81,98.0]*2):
    pass
# ... (полный генератор в репо; здесь — скелет синтеза тона)
```

> Реальный код генераторов и готовые лупы для каждой игры генерируются на этапе «Звук» по таблицам вайба из её ТЗ (§8 каждого документа). Главное правило: **несколько слоёв одного BPM**, синтез на Python, лицензии чистые (своя генерация).

### 11.3. SFX-принципы

- Каждое значимое действие — свой короткий SFX. Синтез: осциллятор+огибающая+шум (щелчки, бульки, колокола) или библиотека CC0 (freesound с указанием авторов).
- Вариация питча ±5% при каждом проигрыше — убирает «роботичность» повторов.
- «Победные» звуки — не дольше 1.5 с; «фоновая музыка успеха» не нужна, нужен акцент.
- Озвучка текста не нужна в MVP (кроме кнопок-подсказок — нет, тоже не нужно; язык: интерфейс ru/en).

## 12. CI/CD и контроль качества сборки

- CI на GitHub Actions (или аналог): каждый PR → `godot --headless` импорт + `--check-only` + юнит-тесты GUT/GdUnit4. Ночная сборка: экспорт AAB для Android + прогон smoke-тестов (авто-старт уровня на headless невозможно — используется Godot test runner с mock-временем).
- Экспорт из CLI: `godot --headless --export-release "Android" build/arm64.aab` (пресеты: `Android` для RuStore APK и `Android AAB` для GP).
- Версионирование: `versionCode` — монотонный: `major*10000 + minor*100 + patch`; `versionName "1.2.3"`. Никогда не понижать versionCode.
- Релизный чек-лист (общий для игр, в доке 04) + ручной прогон на 3–5 реальных устройствах перед выкатом.
