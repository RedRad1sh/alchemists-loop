# 04. Монетизация и публикация (Google Play + RuStore) — общая процедура

Применимо ко всем трём играм пакета. В ТЗ игр (§11 каждого) — продуктовые таблицы монетизации; здесь — как это технически подключить, протестировать и выпустить.

---

## 1. Стратегия: два билда, один код

| | Билд GP (глобальный) | Билд RuStore (РФ) |
|---|---|---|
| Магазин приложений | Google Play | RuStore |
| Платежи | GodotGooglePlayBilling (Google Play Billing) | RuStore Godot Pay + Core (официальный SDK RuStore) |
| Реклама | AdMob (в т.ч. медиация) | Яндекс Mobile Ads (с медиацией; допускается AdMob-адаптер внутри Яндекса) |
| Аналитика | GameAnalytics | GameAnalytics + (опц.) AppMetrica |
| Уведомления/прочее | одинаковые плагины (notification-scheduler, share, inapp-review) | |
| `versionCode` | общий монотонный | тот же номер пакета (можно идентичный versionCode — площадки независимы) |
| ApplicationId | `com.you.alc` (один id на игру) | **тот же** applicationId — подпись та же (см. §2.3) |

Один Godot-проект на игру, **два экспорт-пресета Android**: `GP` и `RuStore`, отличающиеся списком включённых плагинов (биллинг/реклама) и `project.godot`-фичами (`App.is_ru_build()` через `OS.has_feature("rustore")` или define). Каталог SKU и рекламные unit-id берутся из конфига `data/monetization.json` — разные для билдов.

## 2. Платежи (IAP и подписки)

### 2.1. GodotGooglePlayBilling (GP-билд)

- Официальный плагин godotengine: `addons/godot-google-play-billing`, включить в Export → Android → Plugins.
- Инициализация: `GooglePlayBilling.start()` → после `connected` — `querySkuDetails`, `purchase`, слушать `purchasesUpdated`, начислять в `onPurchaseChanged(PURCHASE_ACKNOWLEDGED/… )`; consumables — `consumePurchase`.
- SKU заводятся в Play Console (Products): consumable, non-consumable, subscriptions.
- Тестовые покупки: license-testing аккаунты в Play Console (тестовые лицензии: «always approve», тестовые номера карт не нужны — покупка идёт через тестовую лицензию).
- Авто-возобновляемые подписки (Launch Day «Госконтракт»): обработать `PURCHASE_PENDING`, `pricingChanged`, grace/account hold, продление — клиентский статус обновлять при `queryPurchases` на старте.
- Никакой серверной валидации в MVP не требуется (игры офлайн-дружелюбные); при вводе «серверных валют» (этап 2) — валидировать purchase token на бэкенде через Google Play Developer API.

### 2.2. RuStore Godot Pay (RuStore-билд)

- Официальный SDK платежей RuStore имеет **Godot-плагин**: из репозитория RuStore на GitFlic скопировать `godot_example/android/plugins` → в проект; в пресете сборки Android включить плагины **Ru Store Godot Pay** и **Ru Store Godot Core**.
- Инициализация SDK: требуется `applicationId` и **deeplink scheme** (activity-alias в манифесте, `tools:replace="android:label"`).
- Покупка: `getPurchases`/`purchase`; начисление товара — в колбэке `confirmPurchase` (потребление consumable). Подписки: обработка lifecycle SDK, возврат статуса.
- Карточка товаров создаётся в RuStore Консоли (раздел «Покупки»/подписки); цены в рублях.
- Тестовая среда: RuStore позволяет тестировать покупки в песочнице (тест-режим в консоли), без реального списания.
- Документация SDK: rustore.ru/help/sdk (разделы «Платежи in-app для Godot», «Подписки для Godot»).

### 2.3. Правила, общие для обоих сторов

- **applicationId и подпись keystore** для RuStore-билда должны совпадать с теми, что в консоли RuStore (иначе покупки/обновления не пройдут).
- Один keystore на всю студию (хранить в менеджере паролей, бэкап; без него нельзя обновлять приложения!).
- Единый фасад `Monetization` (autoload): `ready`, `purchase(sku)`, `consume`, `restore()`, сигналы `purchase_succeeded(sku, token)/failed(sku, code)`. Игры не знают, какой провайдер под капотом.
- Идемпотентность: начисление по `purchase_token`; повторный `onResume`-запрос не выдаёт награду дважды.
- **Юридическое:** с 01.02.2026 монетизация через платёжные инструменты RuStore (Pay SDK/Billing) доступна только **ИП и юрлицам** (самозанятым и физлицам приём заявок остановлен с 12.12.2025). Вывод: если планируются IAP на RuStore — нужен ИП (или выпускать RuStore-версию бесплатной + реклама). Google Play для РФ: покупки Google Play недоступны для пользователей в РФ с 2022 г. — для РФ-аудитории основной платный канал = RuStore, для глобальной = GP.

## 3. Реклама

### 3.1. Сети и плагины (актуально на 2026)

- **AdMob (GP-билд):** плагин `godot-mobile-plugins` / godot-admob (community, актуальные версии поддерживают 16kb). Требует AdMob App ID в манифесте (`com.google.android.gms.ads.APPLICATION_ID`).
- **Яндекс Mobile Ads (RuStore-билд):** плагин kovardin/godot-yandex-ads (GitFlic/GitHub, форматы banner/interstitial/rewarded/app-open, поддержка медиации с адаптерами AdMob и др., методы `setUserConsent/setLocationConsent`). При использовании медиации AdMob внутри Яндекса — указать AdMob Application ID.
- Альтернативы/дополнения: AppLovin MAX, VK Реклама (myTarget) — через медиацию Яндекса или отдельные плагины; подключать после первичных замеров eCPM.

### 3.2. Форматы и продуктовые правила (для всех игр)

| Формат | Где | Частота/лимиты |
|---|---|---|
| Rewarded | по желанию игрока за буст | не чаще 1/2–3 мин на игрока; не показывать чаще 15–20 раз/день |
| Interstitial | переходы между экранами/после действий | **не чаще 1/20–25 мин**; не в первые 10–15 минут игры и не в первые 2 дня (ретеншн); не в «священных» моментах (церемонии, real-time окна) |
| Banner | **не рекомендуется** в кликерах (съедает экран, клики-мисклики) | если вводить — только в магазине/профиле, прижат к низу, с возможностью скрыть за IAP |
| App-open | при возврате из фона | опционально, с лимитом и только после 3-го дня |

- Rewarded-механика всегда **незаметно-честная**: награда мгновенная, без «ещё один шаг»; если реклама недоступна (нет сети) — кнопка показывает «нет сети», а не исчезает.
- FPS/пауза: перед показом interstitial — автопауза музыки/таймеров, после закрытия — восстановление; real-time окна не пересекаются с рекламой никогда.

### 3.3. Технический процесс подключения (для каждой игры)

1. Завести аккаунты: AdMob + Яндекс (для РФ) → создать приложения → получить unit-id (тестовые id из документации использовать на этапе разработки!).
2. Плагин → включить → инициализация при старте после consent.
3. Прогреться: загружать rewarded заранее (preload) — показ мгновенный.
4. Трекинг: события `ads_impression{network,format}` — обязательно через Analytics (для сверки с отчётами сети и оптимизации частот).
5. Наблюдать eCPM: первые ориентиры появятся после ~1000 показов; типичный порядок величин rewarded-видео в РФ (2025–2026) — сотни рублей за 1000 показов, interstitial ниже; конкретику смотреть в кабинетах сетей и решать: оставить/выключить формат.

### 3.4. Согласия (consent)

- EEA-пользователи (GP-билд): собственный экран согласия (GDPR) до инициализации рекламы: «Разрешить персональную рекламу / только ненаправленную» → передать в SDK (`setUserConsent`; у AdMob — флаг направления рекламы). Аналитика — в той же политике.
- РФ: требования 152-ФЗ «О персональных данных» и 38-ФЗ «О рекламе»: политика конфиденциальности с перечнем собираемых данных и рекламных партнёров + пункт «Как отключить персонализацию».
- Дети: если игра маркируется 3+ и не исключает детей — EEA: ограничение рекламы для детей (TFCD/child-directed), лучше ставить 6+/12+ и не таргетировать детей рекламой.

## 4. Публикация в Google Play (пошагово, состояние 2026)

### 4.1. Аккаунт и требования

1. Аккаунт разработчика: **$25 разово**. Личный аккаунт (создан после 13.11.2023) обязан пройти **закрытое тестирование: ≥ 12 тестеров, непрерывно 14 дней** — до этого production недоступен. Организационные аккаунты (D-U-N-S) освобождены. Планировать это в роадмапе: **закрытый тест начинать за ~3 недели до релиза**.
2. Техтребования сборки: **targetSdk 36 (Android 16)** для новых приложений и обновлений (с 31.08.2026); minSdk ≥ 24 (наш выбор); **поддержка 16 КБ page size** (проверять в Play Console: предупреждение «App must support 16 KB memory page sizes» не должно появляться после загрузки AAB); AAB-формат (Godot экспортирует AAB из пресета «Android» с галочкой AAB).
3. Данные аккаунта: имя разработчика/студии, контакты, страницы политики конфиденциальности и поддержки (хостинг — свой сайт/GitHub Pages).

### 4.2. Этапы релиза

1. **Play Console → Создать приложение** → название, язык, «Приложение для игр» + заполнить **Анкету рейтинга IARC** (возраст 3+/6+ по ответам).
2. **Закрытое тестирование:** собрать тестеров (12+, активных: открывали приложение за 14 дней), трек Closed testing → пригласить по ссылке → после 14 дней подать заявку на production-доступ (анкета: как тестировали, что исправили). Обычно одобрение 1–7 дней.
3. **Production:** загрузка AAB → данные карточки:
   - иконка 512×512 (32-бит PNG), фичеграфик 1024×500, скриншоты: телефон (мин. 2, лучше 8–10) + планшет (2+);
   - описание: короткое (80 симв.) + полное (с ключевиками, буллеты);
   - категория и жанр;
   - **Data safety form**: какие данные собираются (устройство-id, события, покупки), рекламные SDK, шифрование, удаление данных;
   - «Удаление аккаунта»: если есть аккаунты (никнеймы/серверные данные) — обязан быть способ удалить аккаунт/данные в приложении и по ссылке. Заложить кнопку в настройки всех трёх игр.
4. **Staged rollout:** 10% → 50% → 100% (с мониторингом крашей/рейтинга между шагами). Для обновлений — тот же порядок.
5. Публикация для РФ: Google Play в РФ доступен для скачивания (оплата IAP недоступна) — в карточке указать, что покупки для РФ через RuStore-версию, или не акцентировать.

### 4.3. Политики, частые причины отклонения (чек)

- Нет политики конфиденциальности / битая ссылка.
- Несоответствие заявленного функционала (обещали в описании то, чего нет).
- Рекламные SDK до согласия (EEA) — отклонение/предупреждение.
- Запрос лишних разрешений (не просим ничего лишнего — см. дока 00).
- Крэши при старте на устройствах тестера (проверить слабые устройства до загрузки!).
- Иконка/арт с чужим контентом.

## 5. Публикация в RuStore (пошагово)

### 5.1. Аккаунт

1. Регистрация разработчика: бесплатно (почта/VK ID/номер телефона). Для **монетизации (IAP/подписки)**: нужен ИП/юрлицо + банковские реквизиты + договор; физлица могут публиковать бесплатные приложения и монетизировать рекламой. Подписание документов — через УКЭП.
2. Верификация владельца и (для монетизации) — реквизиты, договор оферты, тестовый платёж.

### 5.2. Карточка приложения (требования RuStore)

| Материал | Требование |
|---|---|
| Иконка | PNG/JPG 512×512, ≤ 3 МБ |
| Скриншоты | PNG/JPG, сторона 320–3840 px, 16:9 или 9:16, ≤ 3 МБ; мин. 2, рекомендуется 5+ |
| Промо-баннер (опц., для разделов) | 1280×720 (16:9), ≤ 150 КБ |
| Короткое описание | ≤ 70–80 символов |
| Полное описание | текст + буллеты; соответствовать функционалу |
| Возрастная маркировка | анкета (0+/6+/12+/16+/18+) |
| Политика конфиденциальности | обязательная постоянная ссылка |
| Категория | выбрать по типу игры |

### 5.3. Загрузка и модерация

1. Экспорт: APK или AAB (RuStore принимает оба; для новых — AAB предпочтителен, поддерживается). Подпись — тот же keystore, что и у будущих обновлений.
2. Консоль RuStore → «Добавить приложение» → заполнить карточку → загрузить → **модерация обычно 3–10 рабочих дней**; отклонения приходят со списком причин (частые: нет политики, мало скриншотов, крэш при проверке, избыточные разрешения, несоответствие описания).
3. Тестирование перед подачей: разослать APK тестовой группе (раздел «Тестирование» в консоли: закрытая группа по ссылке) — реально проверить сценарии покупок в песочнице RuStore.
4. Обновления: versionCode выше предыдущего; чек-лист изменений; повторная модерация (быстрее при «минорных изменениях»).

### 5.4. Выплаты и комиссия

- Комиссия RuStore: **15%** с каждой транзакции; выплаты ежемесячно; минимальный порог — в договоре (порядка 20 000 ₽; для ИП/юрлиц условия в оферте).
- Отчётность по налогам: ИП (УСН 6% / самозанятый 4–6% — применимо только до 01.02.2026 для платежей; далее только ИП/юрлица) — вести самостоятельно; RuStore выдаёт отчётные документы.
- Рекламная монетизация на RuStore — вне платёжных инструментов RuStore: работает для любых аккаунтов, комиссия не взимается.

## 6. Версионирование, релиз-процесс, KPI

- `versionCode = major×10000 + minor×100 + patch` (1.2.3 → 10203); `versionName = "1.2.3"`. Монотонность на обеих площадках.
- Перед каждым релизом: релизный чек-лист (дока 00 §14) + сверка «мягких» правил монетизации + smoke-прогон покупок (GP: license-testing; RuStore: песочница) + проверка уведомлений/оффлайна.
- KPI монетизации (общие цели): ARPDAU, конверсия покупателей (цель 2–4% к 3-му месяцу), доля дохода rewarded/подписки/IAP (для Launch Day цель: подписка ≥ 40% выручки), рекламный ARPDAU. Решение «что крутить» — по данным A/B из ТЗ игр.
- A/B на уровне стора: иконка (2 варианта, через GP experiments), скриншоты, цена (через «предложения» не в РФ — цены задаются по странам в консоли).
- Мониторинг после релиза: краши (Play Console Vitals / Sentry), рейтинг и отзывы (отвечать в течение 48 ч — влияет на ранжирование), удаление негативных паттернов (жалобы на рекламу — снизить частоты).

## 8. Реализация в ALCHEMIST'S LOOP (v0.2)

В проекте `alchemists-loop/` эти рекомендации имеют конкретные точки расширения:

- фасад: `autoload/monetization.gd`;
- Google Play: `platform/google_play_billing.gd`;
- RuStore Pay: `platform/rustore_pay.gd`;
- реклама: `platform/ads_adapter.gd`;
- согласия/сессии/события: `autoload/app.gd`, `autoload/analytics.gd`;
- локальное хранилище: `autoload/user_data.gd`, `game/saves.gd`;
- UI каталога и privacy controls: `game/shop.gd`;
- SKU и частоты: `data/monetization.json`;
- пошаговая установка SDK/deeplink: `alchemists-loop/docs/android/PLUGIN_SETUP.md`;
- KPI, A/B и guardrails: `alchemists-loop/docs/monetization-analysis.md`.

Фасады не содержат store credentials и не симулируют успешную покупку в
production. Локальные `--ads-stub`/`ALCHEMY_ADS_STUB=1` разрешены только для
UI smoke-теста. Перед публикацией обязателен backend receipt validation:
клиентский callback SDK не является доказательством оплаты.
