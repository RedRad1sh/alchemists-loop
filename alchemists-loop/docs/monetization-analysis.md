# Монетизация и аналитика — ALCHEMIST'S LOOP v0.2

Дата фиксации: 16 сентября 2026. Документ связывает ТЗ-01 с тем, что уже
есть в клиенте, и с реализацией в `autoload/monetization.gd`.

## 1. Что было в проекте до этапа

- Игровой цикл уже имеет одну основную валюту — эфир, постоянное «Золото
  мудрецов», дом/декор и rewarded-подобные idle-механики.
- `Saves` писал большой JSON атомарно, но версия была фиксирована на `1`, не
  было отдельного контейнера приватности, экспорта и удаления данных.
- Платёжных/рекламных SDK, consent-флоу и единого аналитического фасада не было.
- `device_id` жил в отдельном открытом файле; на сервере был профиль, но не было
  API удаления/экспорта персональной связи.
- Поэтому прямое добавление кнопки «Купить» было бы опасным: нельзя было бы
  отличить повторный callback покупки от нового и нельзя было бы объяснить
  пользователю, какие данные хранятся.

## 2. Принятая модель

### 2.1. Что продаём

| Продукт | Тип | Рекомендованный тестовый ценовой якорь | Игровой эффект |
|---|---|---:|---|
| `ether_pack_small` | consumable | 99 ₽ | +500 эфира для личных варок |
| `ether_pack_large` | consumable | 199 ₽ | +1500 эфира |
| `sage_gold_pack` | consumable | 149 ₽ | +1 золото престижа; не меняет мировой шанс |
| `starter_bundle` | consumable | 199 ₽ | +500 эфира, +1 золото, янтарная тема |
| `remove_ads` | non-consumable | 299 ₽ | убрать межэкранную рекламу |

Цены в JSON — **ориентиры для карточки**, а фактические цены/налоги/локали
задаются в Play Console и RuStore Console. SKU в JSON — стабильный контракт
между UI и адаптером, его нельзя менять после публикации без миграции.

### 2.2. Rewarded и interstitial

- `source_boost_60`: добровольный ролик → +1 дополнительный ресурс при тапе по
  источнику 60 секунд.
- `extra_brew`: добровольный ролик → +12 эфира (ровно стоимость одной базовой варки v2).
- Rewarded: не чаще одного раза в 150 секунд и не более 5 раз в сутки.
- Interstitial: только через явный `Monetization.show_interstitial(context)`,
  пауза 1500 секунд, не во время варки/открытия. На первых сессиях он не
  вызывается; после теста retention можно включить переходный placement.
- Баннер в основной лаборатории не используется: портретный экран плотный,
  риск мискликов выше дохода.

### 2.3. Жёсткое правило честности

Покупки ускоряют личную книгу, дом и престиж. Они не:

- создают вещество в мировом пуле;
- повышают вероятность первооткрытия;
- обходят серверное решение пары;
- дают место в рейтинге напрямую.

Это сохраняет смысл ключевой фичи «живой мир» и не превращает малую аудиторию
в аукцион.

## 3. Технический поток покупки

1. UI вызывает `Monetization.purchase(product_id)`.
2. Фасад переводит логический id в store SKU и пишет pending запись в
   пользовательский файл `alchemists_loop_user.json` (секция `purchases`).
3. Google Play/RuStore адаптер возвращает нормализованный callback с
   `{provider, sku, token}`.
4. SKU сопоставляется с каталогом. Повторный token от restore/onResume
   отбрасывается по отпечатку `provider:sku:sha256(token)` в журнале покупок
   `alchemists_loop_purchases.json` (см. §6).
5. После выдачи награды вызывается consume/confirm для consumable или
   acknowledge для non-consumable.
6. `purchase_start/success/fail` уходят в Analytics только после согласия.

### Важное ограничение перед production

Клиентские адаптеры готовы, но секреты Google Play Developer API и RuStore
server credentials нельзя помещать в APK. Перед публичным релизом нужен
backend receipt-validation слой:

- Google: отправлять `purchase token` на свой сервер, проверять product/package и
  состояние через Google Play Developer API.
- RuStore: отправлять subscriptionToken/invoice id на свой сервер и проверять
  через API/кабинет RuStore.
- только ответ `valid + not_processed` должен разрешать начисление;
- сервер хранит receipt hash, product, device/user id, store, status,
  processed_at и refund/revoke status;
- клиентская идемпотентность остаётся дополнительным слоем, не заменой проверки.

Сейчас callbacks SDK проходят через общий фасад, что позволяет подключить эту
проверку без изменений UI и core loop. Для локального теста плагинов используйте
store sandbox/license testers; `--ads-stub` и `ALCHEMY_ADS_STUB=1` не включать в
release.

## 4. События аналитики

События стандартизированы в `Analytics.track()` и отправляются только после
согласия. Параметры не содержат nick/device id/email.

| Событие | Параметры | Зачем |
|---|---|---|
| `app_open` | store, consent | разделение GP/RuStore и источник запуска |
| `session_start/end` | source, reason, lengthSec | D1/D7/D30, длина сессии |
| `tap_source` | element, amount | ценность rewarded boost и темп экономики |
| `combine_start` | left, right, source | воронка до варки |
| `combine_try` | left, right, result, output, source | known/new/fail, Aha-moment |
| `purchase_start/success/fail` | sku, store, type, code | конверсия и технические отказы |
| `purchases_restore` | count, store | стабильность восстановления |
| `rewarded_start/finish` | placement, store | rewarded ARPDAU и лимиты |
| `interstitial_start` | context, store | частота и раздражение |
| `ads_error` | format, code | eCPM/availability diagnostics |

Провайдеры: GameAnalytics как общий слой; AppMetrica опционально в RuStore
сборке. В desktop/selftest фасад безопасно работает без SDK.

## 5. Метрики и решения

### Северная звезда

- D1 ≥ 35%, D7 ≥ 12%.
- ≥85% новых игроков делают первую комбинацию в первой сессии.
- Median time to first new recipe ≤15 минут.
- ≥15% игроков D7 становятся первооткрывателями.

### Монетизация

- payer conversion: 2–4% к третьему месяцу;
- rewarded opt-in: 15–30% DAU, без ухудшения D1/D7;
- interstitial share: не более 10–15% сессий после включения;
- ARPDAU и refund rate по каждому store;
- доля покупок `remove_ads` / packs / bundle.

### Guardrails

Отключить placement или вернуть частоту назад, если в A/B:

- D1 падает более чем на 2 п.п.;
- средняя первая сессия короче на 10%;
- жалобы на рекламу растут быстрее rewarded revenue;
- игроки начинают чаще бросать варку после показа рекламы.

### Первые A/B-тесты

1. Rewarded: `+12 эфира` против `source_boost_60`; обе награды проходят через overflow-фасад и не сгорают на капе.
2. Набор новичка: предложение после первого открытия против предложения после
   второго дня.
3. `remove_ads`: 249/299/349 ₽ при неизменном составе продукта.
4. Включение interstitial после 3-го дня против полного отказа от него.

Не тестировать одновременно цену и состав продукта: иначе нельзя понять
причину изменения конверсии.

## 6. Хранение и приватность

Локально:

- `alchemy_save.json` — прогресс и настройки, версия `2`, temp+backup;
- `alchemists_loop_user.json` — случайный install/device id, consent,
  pending-заявки покупок, owned products и лимиты рекламы; затирается при
  «Удалить локальные данные»;
- `alchemists_loop_purchases.json` — журнал покупок: завершённые чеки (ключ
  `provider:sku:sha256(token)`) и granted-отметки «начислено, store ещё не
  подтверждён». Переживает удаление локальных данных: это платёжная защита от
  повторной выдачи, а не поведенческие данные;
- `alchemists_loop_analytics.json` — consent-gated очередь событий,
  создаётся только после согласия;
- сырые purchase token не сохраняются.

Сервер:

- device id нужен для игрового профиля/открытий;
- `GET /api/account/export` возвращает профиль, дом, первооткрытия и echoes;
- `DELETE /api/account?device_id=` удаляет профиль и личные таблицы, а мировые
  элементы сохраняет с анонимизацией авторства.

Публичная ссылка политики задаётся `ALCHEMY_PRIVACY_URL` (или
`application/config/privacy_policy_url`), сейчас в проекте стоит placeholder и
его обязательно заменить до публикации.
