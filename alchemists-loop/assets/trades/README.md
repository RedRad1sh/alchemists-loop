# Окно обмена — визуальные ассеты

## Что здесь лежит

```
assets/trades/
├── pane_tablet.png    512×640   доска-подложка: пиленая доска + прибитый лист бумаги
├── pocket.png         160×200   бумажный карман-«рукав» под миниатюру карты
├── slot_seal.png      120×120   пустая ячейка: записка, запечатанная сургучом
├── cloth_dark.png     256×256   бесшовный тайл тёмного сукна под затемнением
└── *.png.import                  sidecar-файлы Godot для каждого PNG
```

Размеры — @2x от логических 256×320, 80×100, 60×60, 128×128. Логические размеры
— контракт раскладки (`game/social/trade_ui.gd`), физические сверяет пин
`trade textures exported at declared sizes`.

## Пайплайн генерации

Ассеты генерируются вне репозитория (AGENTS.md §28: генератор — не артефакт):

```
outside-repo/trades-svg/
├── gen_trades_svg.py   Python-генератор 4 SVG (stdlib, без <filter>/<pattern>)
├── export.gd           Godot-скрипт: SVG → PNG @2x (ThorVG)
├── preview.gd          контактный лист 1080×760: тайл + все четыре в 0.5x и 1x
├── diag.gd             снимает метрики пинов (distinct / inner / seam) до коммита
└── mutate.gd           мутационная проба: красит PNG-и и проверяет, что пин краснеет
```

Порядок перегенерации:

```bash
python outside-repo/trades-svg/gen_trades_svg.py
Godot_v4.7.2-stable_win64_console.exe --headless \
    --path outside-repo/trades-svg --script res://export.gd
Godot_v4.7.2-stable_win64_console.exe --headless --path alchemists-loop --import
```

`--import` обязателен: без `.import`-сайдкар текстура в свежем worktree не
видна, и пин `trade textures ship .import sidecars` это требует явно.

## Как окно обмена использует ассеты

- **`cloth_dark.png`** — `TextureRect` c `stretch_mode = TILE` поверх затемнения
  экрана: подложка под обе панели, чтобы «затемнение» было тканью, а не цветом.
- **`pane_tablet.png`** — подложка панели игрока и панели друга (одна текстура,
  зеркально по смыслу: «Отдаю» / «Прошу»). Поверх — сетка ячеек.
- **`pocket.png`** — подложка занятой ячейки: карта ложится в «рукав».
- **`slot_seal.png`** — подложка пустой ячейки: сургуч читается как «сюда ещё
  ничего не положили».

## Ограничения, которые уже стоили отладки

- ThorVG не поддерживает `<filter>` и `<pattern>`: зерно, ворс и рваный край
  запекаются геометрией (полигоны, штрихи, точки с сид-джиттером), как на доске
  контрактов. Формулировка спеки про `feTurbulence/feDisplacementMap`
  реализована этим же способом.
- **Ткань тайлится ⇒ каждая нить у границы обязана быть продолжена с другой
  стороны.** Рубчики вельвета идут с периодом 4 (делит 128), и фаза ставит
  границу тайла на СЕРЕДИНУ рубчика: штрих рубчика на x=0 дорисовывается тем же
  цветом на x=S. Если граница попадает между канавкой и рубчиком, кромки
  оказываются двумя независимо нарисованными нитями, и один этот переход
  перекрывает среднее всех внутренних переходов — `seam_x` краснеет на тайле,
  который глазом шва не показывает. Всё, что стоит на левой кромке (рубчик,
  примятый ворс, блик на ворсе), дублируется на x+S; слои с джиттером (пух,
  крап, потёртости, световые пятна) держатся с отступом от кромок.
- **Вельвет без утка.** Поперечные серии (уточные переплетения, скрепляющие
  нити, поперечные «плавающие» нити) дважды превращали ткань в клетчатую
  скатерть: любая горизонтальная регулярность перечёркивает вертикальные
  рубчики в клетку. В тайле нет ни одной серии поперёк рубчиков; поперёк лежат
  только одиночные случайные слубы-узелки, регулярности не дающие. Плавающие
  нити идут ВДОЛЬ ворса, штрихами.
- **Бумага даёт высокочастотный контраст только вертикальными линиями.**
  Длинные горизонтальные прожилки почти не меняют соседа по X: `inner_x`
  держат цепные линии бумажной формы (вертикальные, шаг 8 px). Без них
  лист — гладкий градиент, и пин `trade textures are not flat fills` краснеет.
- **Гистограмма тёмной ткани считается в 5 битах на канал, а не в 4.** Диапазон
  сукна (#0a0608…#8a6a5c) целиком не влезает в 16 коробок на канал, и
  требование «≥24 различных тона» превращалось в требование «будь не тёмным».
  Плоская заливка даёт 1 коробку при любом кванте — мутация «залить PNG
  цветом» по-прежнему красит пин (проверено `mutate.gd`). Запас по тонам даёт
  примятый ворс, блики на гранях рубчиков и потёртости: без них тёмный тайл
  сидит ровно на планке 24.
- Ткань не должна светлеть: это затемнение заднего плана. На светлых лотах
  нитей тайл начинал читаться как клетчатая скатерть и спорил с бумажными
  панелями.

## Приёмка

Проверки лежат в `tests/suite_trades.gd`, секция `_textures`:

- `trade textures load from assets` — все четыре грузятся как `Texture2D`
- `trade textures ship .import sidecars` — сайдкары закоммичены
- `trade textures exported at declared sizes` — @2x размеры совпадают
- `trade textures are not flat fills` — ≥24 тона на сетке 24×24 (квант 5 бит)
  и `inner_x > 0.02`
- `trade paper textures are torn cut-outs` — углы `pane_tablet`/`pocket`
  прозрачны, вертикальная полоса тела непрозрачна
- `trade cloth tile is seamless on both axes` — `seam <= inner * 1.6 + 0.02`
  по обеим осям

Метрики снимаются `diag.gd` до коммита; красность пинов доказывается
`mutate.gd` (три независимые мутации → ровно три красных проверки).
